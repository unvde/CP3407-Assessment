# Project Proposal

## Project Title

**Course Project:** CP3407  
**Product Name:** Reading Compass

## 1. Project Overview

Reading Compass is a web-based application designed to help readers plan, organise and reflect on their reading.

Readers often maintain book lists in notes, spreadsheets or separate applications. These approaches can make it difficult to understand what they are currently reading, what they intend to read next and whether they are making progress toward their plans.

Reading Compass will bring these activities together in one focused application. Users will be able to maintain a personal reading list, organise books by reading status, create reading plans, record progress and write reflections after completing a book.

The application will be developed incrementally using agile software engineering practices.

## 2. Problem Statement

Students and casual readers may collect many book recommendations but lack a simple process for turning those recommendations into realistic reading plans.

Existing methods can be fragmented or provide more functionality than a user needs. A focused solution is required to help users answer four practical questions:

- What books do I want to read?
- What am I currently reading?
- Am I progressing according to my plan?
- What did I learn or think about a completed book?

## 3. Objectives

The project aims to:

- Provide a central location for personal reading plans.
- Help users organise books by reading status.
- Allow users to record measurable reading progress.
- Encourage users to reflect on completed books.
- Present useful reading information through a clear dashboard.
- Deliver the system through planned and reviewable iterations.
- Apply appropriate version control, design, testing and documentation practices.

## 4. Target Users

The primary target users are:

- University students who read for study or personal development
- Casual readers who want to establish consistent reading habits
- Readers who want a lightweight alternative to complex social-reading platforms

Target-user assumptions will be reviewed through interviews during the requirements-analysis stage.

## 5. Proposed Features

### Account Management

Users will be able to create an account, sign in securely and manage basic account information.

### Personal Reading List

Users will be able to add books and organise them using statuses such as:

- Want to Read
- Currently Reading
- Completed
- Paused

### Reading Plans

Users will be able to select books and define personal reading targets or intended completion dates.

### Progress Tracking

Users will be able to record their current reading position and view their progress.

### Reading Notes

Users will be able to save short notes associated with books they are reading.

### Completion Reflection

After completing a book, users will be able to record a rating and written reflection.

### Dashboard

Users will be able to view a summary of current books, recent activity and reading-plan progress.

### Search and Filtering

Users will be able to locate entries by title, author or reading status.

The feature list is preliminary and will be refined after gathering user feedback.

## 6. Proposed Technology Stack

The initial technical proposal is:

- Python
- Django
- HTML5
- CSS3
- JavaScript
- SQLite for development
- Git and GitHub for version control
- Django testing tools for automated testing

The final selection will be justified during the design stage.

## 7. Data and Privacy

The application is expected to store:

- User account information
- User-created book records
- Reading plans
- Reading progress
- Notes, ratings and reflections

The project will apply the following principles:

- Collect only information required by the application.
- Protect account functions using authentication and authorisation.
- Prevent one user from accessing or changing another user’s private records.
- Avoid storing unnecessary sensitive personal information.
- Use secure configuration practices for credentials and deployment settings.
- Use test data rather than real personal data during development.

## 8. Project Scope

The initial scope focuses on personal reading planning and reflection.

The following items are not currently part of the initial scope:

- Commercial book purchasing
- Copyrighted book-content distribution
- Real-time chat
- Public social networking
- Advanced recommendation algorithms
- Native mobile applications

These boundaries keep the project achievable within the available time and development capacity.

## 9. Development Approach

The project will use an iterative agile process.

Work will be represented by user stories, prioritised according to user value and estimated effort. Each iteration will include planning, implementation, testing, progress tracking and reflection.

Project evidence will be maintained through GitHub documentation, issues, meaningful commits, design artefacts, test results and iteration records.

## 10. Success Criteria

The project will be considered successful if:

- Target-user needs are translated into clear user stories.
- The planned core features are delivered within the project schedule.
- Users can manage a personal reading list and update reading progress.
- Access to private user records is appropriately controlled.
- Delivered functionality is supported by automated and acceptance testing.
- The interface is understandable and usable for the target audience.
- Project decisions and iteration outcomes are clearly documented.
