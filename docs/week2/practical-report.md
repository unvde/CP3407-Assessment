# Practical 2 — Requirements Analysis

## Task One: target-user feedback

The team consolidated feedback about book discovery, repeated data entry, privacy, intentional sharing, contextual discussion and recommendation quality. The method and findings are documented in [`interview-findings.md`](interview-findings.md).

## Task Two: formal User Stories

Nine requirements were converted into titled User Stories with course priorities, acceptance criteria and development-day estimates. They are allocated across three seven-day iterations in [`requirements-backlog.md`](requirements-backlog.md).

## Planning rationale

1. Build authentication, canonical catalogue data and private ownership first.
2. Add public discovery, reviews and intentional list sharing once privacy boundaries exist.
3. Add forums, personalisation, moderation and production delivery last because they depend on the earlier data and permission model.
